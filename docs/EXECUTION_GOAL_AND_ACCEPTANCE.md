## Goal 声明（可直接作为 goal 的 objective 与完成判据）

**Objective**：在 strata 工作副本严格落地 `docs/HARNESS_ROADMAP.md` 阶段一的 H1–H4 四个宿主工作包：按序逐包实现、独立提交；每包通过机械门禁、行为验收、测量验收三列；终审四项审计零红灯。

**Completion criterion**：(1) 验收矩阵 4 行全部"绿"且每格附命令级证据；(2) 每包附前后测量（按测量协议的指标对）；(3) 越权审计零改动（`serve/`、`strata_cli/`、vendored 插件均不得触碰）；(4) 默认路径审计通过——四个开关全部关闭时，行为与上一版本一致；(5) `npm test`（apps/host）全绿。五条缺一即 goal 未完成。

## 执行纪律

- 顺序：H1 → H2 → H3 → H4；一包一提交；提交说明含该包理解确认表与证据清单。
- 禁区（终审越权审计对象）：`serve/`、`strata_cli/`、`integrations/harness/profile/` 的上游 bundle 声明、全部 vendored 插件（含 dsh-infinite-gen-4）、DSH 自身源码。
- 硬规则：每个工作包由新增设置项驱动；开关关闭时行为与上一版本一致；测量数字必须附 "Measured on:" 块（硬件、模型、Strata 版本、负载）；未运行的验证如实标注。
- 遇歧义：停下记录问题，禁止猜测实现。

## 验收矩阵

| 包 | 机械门禁（全绿+附命令） | 行为验收（场景级） | 测量验收 |
| --- | --- | --- | --- |
| H1 | `npm test`（apps/host）+ 新增单测 | 脚本化会话单调用循环以停止卡片结束而非挂死；正常连续读不同文件不误伤（计数只对"完全相同调用"累加） | 循环场景从挂死到终止的轮数对比 |

## 第 4 关：终审四审计

1. 完整性：ROADMAP 阶段一表逐项核销。
2. 回归：`apps/host` 全量 `npm test` 通过；既有测试零回退。
3. 越权：`git diff --stat` 对照禁区清单 = 零改动。
4. 默认路径：四开关全关时，与上一版本行为一致（用同一脚本化会话在开关开/关两种状态下对比事件流）。

## 审查协议（评审会话使用）

- 红队规则：逐项索要证据（命令+关键输出）；抽查 ≥2 个新增测试断言原文；确认每个阈值走设置项而非散落常量；核对默认值与本文一致。
- 不通过处置：任一格红 → 打回该包；连续两格红 → 暂停，回读第 0 关重答理解八题。
- 阶段二门槛（记录，不在本 goal 执行）：上游 DSH WP1–WP8 全部落地并升级 pin 版本后，按 ROADMAP 阶段二删除 H1 等被取代兜底——漂移测试失败即删除清单。

## 理解八题答案键

- A1：默认 12；只对"完全相同的 tool call"（同名工具+完全相同参数）连续累加；读不同文件参数不同、不累加，故不误伤。
- A2：默认 3；触发后停止自动压缩并出错误卡片，会话保持可用（用户输入不阻塞）。
- A3：引擎 `count_tokens` 可用时附实测 token 数；不可用时降级为字符数并注明"token 数不可用"。
- A4：返回值必须与 `context-fit.mjs` 实际执行的预算完全一致；不得新增审批——它是只读查询，加审批会打断心流且无风险收益。
- A5：`TESTED_CONTEXT = 32768`、`OUTPUT_CAP = 4096`、`COMPACT_AT = 15000`；在 `strata_cli/launch/harness.py`。
- A6：机制归上游单一归属，宿主重实现会造成分叉（LESSONS/ROADMAP 责任划分表）；上游落地后由 pinned 漂移测试故意失败来发现，失败项即删除清单。
- A7：新特性 opt-in、默认路径与上一版本字节一致；四包全部由新增设置项驱动，关闭即回退旧路径。
- A8：不重实现上游机制全量逻辑；不触碰 vendored 插件；不改 `serve/`、`strata_cli/`、`integrations/harness/profile/`（阶段三另行立项）。
